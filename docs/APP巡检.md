# APP 巡检

在现有工作台左侧选择 **APP 巡检**。顶部 Ego 设备 IP 用于原有设备功能；本页单独选择 USB 调试手机，避免混淆。

## 自动检查

### 全量巡检按钮

点击 **全量巡检**，会切换到全量自动模式并按本轮配置启动：先执行3项框架检查，再执行9项设备流程。先选手机、配置任务编号和指定EGO，勾选空闲确认。参数修改、实际采集和上传仍需分别勾选；未允许的项目记为未测。缺少条件时按钮会给出明确提示，不会暗中启用操作。

游客登录5项要求退出账号，独立预览3项要求停留在指定预览页面，因此需另选对应模式执行；65项人工清单也不会算作全量自动结果。若同时勾选录制和上传，配置中的手机TF卡目录须留空，运行到上传阶段再选择本轮新记录，避免锁定旧记录。执行中遇到登录、网络和换卡时，按提示处理后点“已完成，继续”。

现已增加可实际操作APP的扩展流程：任务、设置与日志、指定SN连接配网、参数写入恢复、短采集、测试文件备份/写入/上传及本地MCAP校验。点“流程配置”填写本轮参数；需要人工登录、换网或插卡时会暂停，完成后点“已完成，继续”。参数、采集和上传需分别勾选。详细范围见 `D:\app-test-framework\docs\扩展巡检脚本.md`。

仓库已包含 `app-test-framework/` 源码，在项目目录执行 `powershell -ExecutionPolicy Bypass -File .\install-app-tests.ps1` 安装。工作台优先选择仓库内已安装的框架，否则兼容本机已有的 `D:\app-test-framework`，也可手动选择。使用该框架自己的 `.venv`，不把 Appium 等依赖装进工作台环境。配置示例不包含真实任务、设备SN或账号，新电脑需自行配置。

- **框架自检**：3 项配置逻辑检查，不操作手机。
- **LivFlow 基础巡检**：5 项，包括空登录校验、三个游客页面导航和语言切换。会重启 APP。先结束采集及上传，退出测试账号并将语言设为中文，再勾选手机空闲确认。
- **LivFlow 预览检查**：3 项，只读已连接状态。需要手机和 EGO 已接入无密码“灵生测试”网络，APP 停在中文双目预览页。不会自动配网、连接或采集。

点击“刷新手机”，只列出 ADB 已授权设备；也支持明确输入序列号。点击“执行自动检查”后可查看逐项结果和进度。停止会终止本次测试子进程及其子进程，已记录结果保留，未执行项记为未测。关闭工作台前需等待停止完成。同一目录下多个工作台实例不能同时执行 APP 自动检查。

## 完整巡检清单

点击 **新建完整巡检清单**，得到 65 项全新清单，全部为“未执行”，不会继承上一次的通过结果。

选中项目，在底部选择结果、填写实际观察，再点击“保存本项”。每次保存会更新 JSON、CSV 和 HTML。参考范围来自已执行的 LivFlow 巡检，仅用于提示检查范围，不代表新一轮结果。扩展流程只自动执行其明确列出的步骤，不代表65项全部自动化；登录、物理插拔卡、固件升级和未覆盖的专项仍需人工配合或记录。

账号密码在手机上输入，不写在清单、备注或报告里。记录的“通过”只覆盖实际执行的步骤，不等同完整产品验收。

## 历史与报告

- “历史巡检”可加载自动记录和人工清单。自动记录只读；人工清单可继续填写。
- 初次集成的 2026-10-21 完整巡检结果（49 通过、5 待确认、11 未测）以只读历史记录提供，不可覆盖。
- “打开本轮报告”显示本轮结果、CSV 下载、自动详细报告及截图证据入口。
- 报告提供概览数字、问题与待确认列表、按结果筛选、文字搜索、截图缩略图及打印/保存PDF。失败与待确认项优先显示，完整技术记录默认折叠；未完成项不计入通过。
- “通过占比”仅针对本轮已列出的检查，不代表全部APP功能覆盖率。文件前后对比单独显示消息与元数据校验结果。
- 新记录保存到本项目 `out/app-patrol/<时间与随机编号>/`，与原有设备报告分开。
- 运行框架与工作台须保留在配置的位置。框架尚未实现的用例不会被界面伪装为已自动执行。

## 启动

原来的“启动测试台.bat”继续可用，重新打开后会出现 APP 巡检页。也可双击“启动APP巡检.bat”，直接进入该页。

开发验证：`.venv-gui\Scripts\python.exe -m unittest test_app_patrol -v`。这些集成测试不操作手机。完整界面渲染沿用 `app.py --screenshot <输出路径>`。
