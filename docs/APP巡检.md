# APP 巡检

在现有工作台左侧选择 **APP 巡检**。顶部 Ego 设备 IP 用于原有设备功能；本页单独选择 USB 调试手机，避免混淆。

## 自动检查

### 全量巡检按钮

点击 **全量巡检**，会依次执行3项框架、4项游客、1项USB空设备扫描和9项设备流程。已登录时先退出并验证登录页，后续设备流程需要时会提示重新登录。先选手机、配置任务编号和指定EGO，勾选空闲确认。参数修改、实际采集和上传仍需分别勾选；未允许的项目记为未测。缺少条件时按钮会给出明确提示。

游客登录5项要求退出账号，独立预览3项要求停留在指定预览页面，因此需另选对应模式执行；65项人工清单也不会算作全量自动结果。若同时勾选录制和上传，配置中的手机TF卡目录须留空，运行到上传阶段再选择本轮新记录，避免锁定旧记录。执行中遇到登录、网络和换卡时，按提示处理后点“已完成，继续”。

现已增加可实际操作APP的扩展流程：任务、设置与日志、指定SN连接配网、参数写入恢复、短采集、测试文件备份/写入/上传及本地MCAP校验。点“流程配置”填写本轮参数；需要人工登录、换网或插卡时会暂停，完成后点“已完成，继续”。参数、采集和上传需分别勾选。详细范围见 `D:\app-test-framework\docs\扩展巡检脚本.md`。

仓库已包含 `app-test-framework/` 源码，在项目目录执行 `powershell -ExecutionPolicy Bypass -File .\install-app-tests.ps1` 安装。工作台优先选择仓库内已安装的框架，否则兼容本机已有的 `D:\app-test-framework`，也可手动选择。使用该框架自己的 `.venv`，不把 Appium 等依赖装进工作台环境。配置示例不包含真实任务、设备SN或账号，新电脑需自行配置。

在“流程配置”选择 Wi-Fi 名称及“免密码网络”或“加密网络”。加密网络会暂停等待在手机输入密码；密码不会存入工作台配置。脚本在预览阶段核对手机连接的 Wi-Fi 名称和安全类型；仅沿用已连接设备时不会声称本轮重新配网。勾选“要求本轮重新配网”可确保分别执行配网步骤，验证两种网络应各执行一轮。

- **框架自检**：3 项配置逻辑检查，不操作手机。
- **LivFlow 基础巡检**：5 项，包括空登录校验、三个游客页面导航和语言切换。会重启 APP。先结束采集及上传，将语言设为中文，已有登录态会先退出，再勾选手机空闲确认。
- **游客模式与空登录校验**：4 项，检查空登录、游客任务提示、蓝牙与 USB 入口切换及“我的”页入口。已有登录态会先退出，无法识别退出入口或确认框时会提示在手机上退出；登录表单不保存截图或输入内容。入口可见不代表外设已连接或采集成功。
- **USB 相机无设备扫描**：1 项，验证没有 USB 相机时的扫描提示；相机权限需要在手机处理。已连接相机时跳过空设备断言，实际连接和采集需要单独测试。
- **LivFlow 预览检查**：3 项，只读已连接状态。需要手机和 EGO 已接入无密码“灵生测试”网络，APP 停在中文双目预览页。不会自动配网、连接或采集。

点击“刷新手机”，只列出 ADB 已授权设备；也支持明确输入序列号。点击“执行自动检查”后可查看逐项结果和进度。停止会终止本次测试子进程及其子进程，已记录结果保留，未执行项记为未测。关闭工作台前需等待停止完成。同一目录下多个工作台实例不能同时执行 APP 自动检查。

## 可识别状态自动继续

在 APP 巡检页的「本机测试账号」下拉列表选择账号，或使用旁边的「新增」「编辑」「删除」管理账号。香橙派巡检在「主机常规 · 账号专项」维护自己的列表，选中账号后还需勾选正反向登录测试。两个列表均明文保存在 `%LOCALAPPDATA%\EgoStdTestkit`，APP 使用 `test-accounts.json`，香橙派使用 `orangepi-test-accounts.json`。旧记录保留在 APP 列表中。

需要登录的设备流程可从启动工作台的进程环境读取 `LIVFLOW_TEST_PHONE` 和 `LIVFLOW_TEST_PASSWORD`，也可设置 `LIVFLOW_TEST_ROLE` 为手机页面上的身份名称。手机号使用数字，密码支持不含空格和 `%s` 的可打印 ASCII 字符。脚本仅在识别到空登录表单时自动填写，遇到身份或登录结果无法确认时暂停。请使用专用测试账号，凭据无需填入巡检配置。

等待登录或切换语言时，若连续两次识别到可点击的“任务”和“我的”主页入口，自动继续；等待手机接入指定 Wi-Fi 时，若连续两次读取到目标 SSID，自动继续；等待预览时，若连续两次识别到双目预览文字，自动继续。页面变化或读取失败不会作为完成；仍可使用“已完成，继续”。识别到主页只表明页面可见，业务登录状态仍由后续流程检查。

TF 卡换插、目录授权、加密 Wi-Fi 密码等无法凭上述条件独立确认的环节仍需人工操作和继续确认；自动继续不会代替实采、文件匹配或上传结果检查。

## 完整巡检清单

### 肌电手环专项

APP 巡检页面的“新建肌电手环专项清单（人工记录）”建立独立的 23 项清单，覆盖版本和手环身份、连接、信号、采集、数据、上传及稳定性。全部从“未执行”开始，选中项目后可查看检查提示并手工记录证据；这些项目不是自动测试，也不代表产品当前版本已实现对应功能。

该清单不安装 APK，不改变原有 LivFlow 测试项目；完成实际适配需要连接明确的平板及手环，确认 APP 页面、手环协议和判定标准，再逐项开发和验证自动化。记录版本和设备身份；无法核实的功能记为未测或待确认。

点击 **新建完整巡检清单**，得到 65 项全新清单，全部为“未执行”，不会继承上一次的通过结果。

选中项目，在底部选择结果、填写实际观察，再点击“保存本项”。每次保存会更新 JSON、CSV 和 HTML。参考范围来自已执行的 LivFlow 巡检，仅用于提示检查范围，不代表新一轮结果。扩展流程只自动执行其明确列出的步骤，不代表65项全部自动化；登录、物理插拔卡、固件升级和未覆盖的专项仍需人工配合或记录。

账号密码在手机上输入，不写在清单、备注或报告里。记录的“通过”只覆盖实际执行的步骤，不等同完整产品验收。

## 历史与报告

- “历史巡检”可加载自动记录和人工清单。自动记录只读；人工清单可继续填写。
- 初次集成的 2026-10-21 完整巡检结果（49 通过、5 待确认、11 未测）以只读历史记录提供，不可覆盖。
- “打开本轮报告”显示本轮结果、CSV 下载、自动详细报告及截图证据入口。
- 报告提供概览数字、问题与待确认列表、按结果筛选、文字搜索、截图缩略图及打印/保存PDF。失败与待确认项优先显示，完整技术记录默认折叠；未完成项不计入通过。
- “通过占比”仅针对本轮已列出的检查，不代表全部APP功能覆盖率。文件前后对比单独显示消息与元数据校验结果。
- 新记录保存到本项目 `out/app-patrol/<时间与随机编号>/`，与原有设备报告分开。
- 运行框架与工作台须保留在配置的位置。框架尚未实现的用例不会被界面伪装为已自动执行。

## 启动

原来的“启动测试台.bat”继续可用，重新打开后会出现 APP 巡检页。也可双击“启动APP巡检.bat”，直接进入该页。

开发验证：`.venv-gui\Scripts\python.exe -m unittest test_app_patrol -v`。这些集成测试不操作手机。完整界面渲染沿用 `app.py --screenshot <输出路径>`。


## APP 版本更新

APP巡检页新增“APP版本更新”区域：先在上方明确选择平板，再选择本机APK，点“检查版本”，核对包名、当前版本、APK版本后，确认平板没有采集/上传，点“安装更新”。

安装使用明确序列号的 `adb install -r --no-streaming`，保留数据，不自动卸载、不清除数据、不允许降级。只接受 LivFlow 包名，签名不一致会停止并提示提供同签名APK。设备切换或文件变化后必须重新检查。巡检与更新共用执行锁；安装采用后台线程，关闭工作台前需等操作结束。

安装后回读versionName/versionCode，再解析启动入口启动APP并核实进程；报告记录APK SHA256、安装前后版本及验证结果，保存在out/app-updates/<编号>/update.json。完整版本回归仍需另跑APP巡检，安装成功不代表业务功能全部通过。


## 页面状态与点击恢复

APP流程仍通过ADB控件树操作，不使用设备后端API替代UI验收。页面识别覆盖登录、已连接设备、配网、扫描、预览、任务、采集中、权限弹窗及系统文件选择器。

点击排除禁用和不可见节点，同名目标不唯一时停止；支持resource-id精确定位。真正点击前重新读取树，确认目标位置与页面状态稳定，避免使用旧坐标。每步ADB读取受总等待期限约束；未识别页面持续不变会提前结束并取证，不无限等待。

连接回调若已进入双目预览，直接核对目标网络和预览，不再等待配网页；若到达已连接卡片，先核对SN，再选择查看设备。人工填写密码后若已进入预览，不重复点击连接。明确要求重新配网时，只验证已有预览不会算成新配网通过。

这是一组受控状态分支，不是能任意推断所有页面的AI代理。未知页面、权限/密码和物理换卡仍可能需要人工；不会通过乱点、断开设备或跳过真实断言换取流程完成。完整真机流程需要针对本轮App/设备再回归。
