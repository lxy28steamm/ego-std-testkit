# LivFlow 扩展流程自动化

这些是会实际操作 APP 的脚本，不是人工清单回放。结果只根据本次断言生成。

## 工作台入口

在 Ego-Std 测试工作台选择“APP 巡检”，自动检查列表现已增加：

| 流程 | 自动操作 | 人工条件 |
|---|---|---|
| 任务流程（3个用例） | 搜索指定任务、清空搜索、状态/时长筛选、重置、任务详情、统计刷新 | 账号登录；配置测试任务编号 |
| 设置流程（2个用例） | 切换英文并恢复中文；按已安装包核对版本；异常日志筛选、刷新及导出；核对导出文件 | APP为中文、允许保存手机日志 |
| 设备连接（1个用例） | 扫描指定SN、连接、选择已保存网络/开放网络、配网、进入双目预览 | 指定SN；多设备、网络密码或手机换网需要人工处理 |
| 参数流程（1个用例） | 读取参数、切换IMU频率、保存并重读、恢复原值并重读 | 单独勾选允许临时修改参数；设备可连接 |
| 短采集（1个用例） | 连接指定EGO、进入指定任务、请求开始、确认采集中、短时后台返回、结束并确认保存提示 | 单独勾选录制；TF卡放回EGO后继续 |
| 上传（1个用例） | 指定任务、读取一组MCAP及源标定/JSON、上传前备份、CRC校验、写入并上传、后台返回、核对结果、前后消息及元数据对比、防重复 | 单独勾选改写并上传；TF卡插手机并明确选择一条测试目录 |
| 本地文件（1个用例） | 完整读取MCAP、CRC、各topic数量/跨度/时间戳倒退；可对比写入前文件及元数据源内容 | 本地MCAP；可选写入前文件，保留原采集目录结构 |

“扩展流程巡检”组合执行上述9个设备流程用例。参数、录制和上传没有单独勾选时会记为未测，不会暗中执行。文件校验是独立流程。没有自动化固件升级、删除、强杀录制、断电、批量破损文件和跨账号测试。

## 运行前

1. 点“流程配置”，填本轮任务编号、指定EGO SN、测试Wi-Fi名称；不填账号密码。
2. 选择ADB已授权手机，确认没有进行中的采集、上传。
3. 选择要运行的流程；需要的写入、录制或上传操作分别勾选。
4. 执行后如果显示“等待人工操作”，按提示在手机登录、换网或选择目录，再点“已完成，继续”。旧的继续信号不能解锁新步骤。

手机自动化期间不要同时点击APP。脚本不选择任意任务、不连接任意SN。Flutter未分离的“采集数据”卡片使用页面内容及滚动终点校验后按实际内容区域定位；如果页面结构改变会停止并留证据，不连续盲点。

短采集的秒数是确认开始后的流程等待配置，截图、页面切换和结束命令存在额外耗时，不能作为精确定时录制使用。本次配置15秒，APP结束页显示39秒；最终文件时长需插卡读取后确认。若底部导航被Android系统栏遮挡，脚本会暂停，需要确认无录制或上传后重启APP恢复布局。

## 停止和数据保护

- “停止本次检查”先发出协作停止请求；短采集会尝试结束设备录制，参数流程会尝试恢复原值。若无法确认，报告会明确失败，并跳过后续流程。
- 协作停止超过90秒仍不退出时才终止测试进程；此时需要人工核实设备。不能将终止脚本等同于设备已经停止。
- 上传开始后停止脚本，不等于手机后台上传停止；不要直接拔卡，应在手机确认。
- 上传前只备份明确选择的单条测试目录。必须备份和校验成功后才点击写入；历史记录、原始备份不删除。
- UI密码框和日志正文不做截图；日志只导出到手机，不复制正文到报告。
- 频率设置回读、消息时间戳连续性，不等同于实际采样频率或传感器物理同步验证。上传完成状态也不等同于转换、质检或云端对象哈希验证。

## 文件及命令行

- `framework/livflow_flow.py`：可复用的页面定位、等待、人工继续、任务、设置、连接、采集、参数及上传流程。
- `framework/recording_check.py`：MCAP及元数据检查。
- `tests/test_livflow_workflows.py`：9个设备流程用例。
- `tests/test_livflow_files.py`：本地文件校验用例。
- `config/patrol.json`：无凭据的配置示例。工作台实际配置保存在其 `out/app-patrol/flow-config.json`。

运行结果保存在工作台 `out/app-patrol/<本轮编号>/`，包含分项结果、HTML/CSV、截图及上传前后副本。没有执行的项目会记未测；已有文件已上传时会跳过实际再传，不伪报一次新的上传成功。

命令行可使用工作台的 `app_patrol_engine.py --framework D:/app-test-framework --mode flow_tasks --serial <明确序列号> --flow-config <JSON路径>`。模式支持 flow_tasks、flow_settings、flow_connect、flow_parameters、flow_record、flow_upload、flow_all、files；写操作分别需要 --allow-parameters、--allow-record、--allow-upload。

GUI会处理人工继续。命令行等待时，session.json 的 waiting.gate 是本次等待标识；将 `{"gate":"对应标识"}` 写入同目录 resume.json 才会继续。取消请使用 --cancel-file 指定的信号文件，不要直接杀进程。
